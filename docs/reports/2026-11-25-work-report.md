## 4. 対局の流れ（`WalkMatch`）

カウントダウン、制限時間、時間切れ、数える、結果、リスタートを1つの部品にまとめました。

### 状態の移り方

```
Countdown（3秒、操作できない）
  → Playing（3分、操作できる）
  → Settling（時間切れ。持ち石を落とし、盤の石が止まるのを待つ）
  → Finished（数えて勝敗を出す。1秒後からボタンで次の1局）
```

### 主なコードの読み方

`Enter(Phase next)`（状態に入るときに1回だけ呼ばれる）

| 行 | 何をしているか |
|---|---|
| `Current = next; phaseTime = 0;` | 今の状態を切り替え、その状態に入ってからの秒数を0に戻す |
| `if (input != null) input.enabled = next == Phase.Playing;` | 対局中だけ入力を有効にする。無効にすると`LocalWalkInput.OnDisable`が走り、移動が0になる |
| `if (next == Phase.Settling) { SetText(bannerText, "TIME UP"); DropHeldStones(); }` | 時間切れの表示を出し、全員の持ち石を落とす |
| `if (next == Phase.Finished) ShowResult();` | 数えて勝敗を出す |

`AnyMoving()`（盤の上で動いている石があるか）

| 行 | 何をしているか |
|---|---|
| `if (stone.IsFlipping) return true;` | 裏返っている途中の石があれば、まだ数えない |
| `if (stone.status != StoneStatus.OnBoard \|\| body == null \|\| body.isKinematic \|\| body.IsSleeping()) continue;` | 盤の上にない石と、物理が眠っている（完全に止まった）石は調べない |
| `if (body.linearVelocity.sqrMagnitude > limit \|\| body.angularVelocity.sqrMagnitude > limit) return true;` | 速さか回転が`settledSpeed`（0.05）を超えていれば、まだ動いているとみなす |

時間切れのあとは、最短1.5秒、最長4秒待ちます。滑っている石が止まって捕獲を起こすことがあるので、それを待ってから数えるためです。

### 持ち石を落とす処理（`CarryAuthority.ForceDrop`）

掴む・離すは`CarryAuthority`を通す決まりなので、`WalkMatch`は`WalkPlayer.Detach`を直接呼ばず、`ForceDrop`を通します。`ForceDrop`は`TryRelease`の「投げない」側と同じ処理で、溜めていても投げにしません。入力を先に止めて移動を0にしているので、石は正面にそのまま落ちます。

### 確かめたこと

- 6秒の短い対局で、カウントダウン→GO!→タイマー→TIME UP→結果、の順に進んだ。
- 時間切れの瞬間に構えていた石が手から落ち、盤の上で白を1つ挟んで、結果が「BLACK WINS 5 - 2」になった。
- サブエージェント（reviewer）のレビューで指摘された5件のうち、4件を直した。残る1件が「時間切れのときの持ち石」で、上の決定になった。

### 6.2 トゥーンシェーダー（`WalkAssets/Toon/ToonLit.shader`）

サブエージェントに書かせ、エディタでコンパイルを確かめました。パスは5つです。

| パス | 役割 |
|---|---|
| ForwardLit | 光を2段（明部と影）に分けて塗る。影は黒ではなく`_ShadowTint`を掛けた色 |
| Outline | 裏返した外殻を、画面のピクセル幅で押し出して輪郭線にする |
| ShadowCaster | 影を落とす |
| DepthOnly / DepthNormals | 深度と法線を書く |

塗りの中心（ForwardLitのフラグメント）の読み方：

| 行 | 何をしているか |
|---|---|
| `Light mainLight = GetMainLight(shadowCoord);` | 太陽の光と、その点が影に入っているかを取る |
| `half light = ndotl * mainLight.shadowAttenuation * mainLight.distanceAttenuation;` | 面の向き（光とのなす角）と影の量を掛けて、明るさを0〜1で出す |
| `half q = ToonBands(light);` | 明るさを段に丸める。2段なら、0.1を境に0か1になる |
| `color = albedo * lerp(_ShadowTint, 1, q) * mainLight.color;` | 明部は元の色、影は元の色×影の色。影を黒くしない |
| `color += albedo * SampleSH(n) * _ReceiveAmbient;` | 環境光を足す。強すぎると影が埋まるので0.25にした |
| `color = lerp(color, _FlashColor.rgb, _FlashColor.a);` | 演出用のフラッシュ（6.6を参照） |

### 6.3 光と影で分かったこと

最初の画面は白っぽく、影が見えませんでした。原因を1つずつ切り分けました。

1. 環境光の寄与を0.6→0.25に下げた。締まったが、影はまだ見えない。
2. 盤だけ標準のLitに替えた。キャラクターの影は出たが、石の影は出なかった。
3. 光を高さ10°まで下げた。影が長く伸びて、はっきり出た。シェーダーは正しかった。

原因は、光の向きでした。光をカメラ側から当てていたので、影が石の向こう側に落ち、厚さ0.36の薄い石の陰に隠れていました。光を盤の奥から当てるように変えて（回転(40, 60, 0)）、影がカメラ側に三日月形に出るようにしました。あわせて、影を描く範囲を90→75、影の補正を0.2、カスケードを2にし、輪郭線のギザギザを抑えるMSAA 4倍を入れました。

### 6.4 キャラクター（`ToyFigureSetup.cs`、`ToyFigureMotion.cs`）

カプセルを、プリミティブで組んだ2頭身の人形に替えました。当たり判定（`CharacterController`、半径0.25）は変えていないので、押したときの物理の結果は前と同じです。

- 部品は、体、クリーム色の頭、点の目、ニット帽、黄色のポンポン、手、足。古いカプセルは消さずに非表示にしている。
- 見た目は1.8倍にした。1.0倍、1.5倍、1.8倍をゲームのカメラで比べて決めた。頭は大きくても、石が低い（厚さ0.36）ので重ならない。
- 顔は光の反対側を向くので影の色で灰色になった。顔と手だけ環境光を0.6にして、クリーム色に戻した。

`ToyFigureMotion.LateUpdate`の読み方（見た目の部品だけを動かす）：

| 行 | 何をしているか |
|---|---|
| `float speed = ... delta.magnitude / dt / player.moveSpeed` | 前のフレームからの移動量で、歩く速さを0〜1で出す。入力ではなく実際の動きを見るので、阻まれて止まると揺れも止まる |
| `phase += dt * stepRate * Mathf.PI * ...` | 歩く速さに応じて、足運びの位相を進める |
| `body.localPosition = bodyRest + Vector3.up * bounce * bobHeight * speedBlend;` | 一歩ごとに体を弾ませる（`bounce`は位相のsinの絶対値） |
| `body.localRotation = Quaternion.Euler(readyLean * readyBlend + ..., 0, step * waddle * speedBlend);` | 歩くと左右に揺れ、構えると前かがみになる |
| `if (holding != wasHolding) squash = 1;` | 掴んだ・離した瞬間に、体をぷにっと縮める |
| `Foot(...)` / `Hand(...)` | 足を交互に前後させる。石を持つと両手を前へ出す |

### 6.6 手ざわり（`ToonFx.cs`、`StoneFeel.cs`）

演出のテクニックは、サブエージェントにウェブで調べさせました。そこから採った方針は次の3つです。

- 強さは、起きる頻度に反比例させる（確定はごく控えめに、裏返りがいちばん派手に）。
- 対局中は時間を止める演出（ヒットストップ、スロー）を使わない。2人が同時に動くので、もう一方の操作まで止めてしまう。
- 形の変化は10〜20%以内で、0.1〜0.2秒で戻す。

**石を伸び縮みさせる仕組み**: 石は1つのオブジェクトに、見た目と当たり判定と物理が同居しています。大きさを変えると当たり判定も変わるので、シェーダーの中で、描く頂点だけを伸び縮みさせています。

| 場所 | 行 | 何をしているか |
|---|---|---|
| `ToonLit.shader` | `float3 PopOS(float3 positionOS) { return positionOS * _Pop.xyz; }` | 描く頂点の位置に、軸ごとの倍率を掛ける |
| `ToonLit.shader` | 全5パスで`input.positionOS.xyz`を`PopOS(...)`に置き換え | 塗り、輪郭線、影が、一緒に伸び縮みする |
| `ToonFx.cs` | `block.SetVector(PopId, ...)` / `renderer.SetPropertyBlock(block);` | 石ごとの倍率を、MaterialPropertyBlockで1つずつ上書きする。マテリアルの共有はそのまま |
| `ToonFx.cs` | `if (!running) finished.Add(renderer);` → `renderer.SetPropertyBlock(null);` | 演出が終わった石は上書きを外して、まとめて描く仕組み（SRP Batcher）に戻す |

**どの出来事に何をするか**（`StoneFeel`がイベントを受けて実行）：

| 出来事 | イベントの出どころ | 演出 |
|---|---|---|
| 掴む | `CarryAuthority.StoneGrabbed` | 石が少し伸びて戻り、白く光る。プレイヤーの色の粒 |
| 投げる | `CarryAuthority.StoneThrown` | 石が黄色に光り、黄色の粒 |
| 着地・衝突 | `CarryStone.Impacted` | 速さ2.5以上のときだけ、潰れて戻り、卓の色の粒。1つの石は0.12秒に1回まで |
| 裏返り始め | `CarryStone.FlipStarted` | 小さく沈む（予備動作） |
| 裏返り終わり | `CarryStone.FlipEnded` | 弾んで白く光り、黄色と白の粒。同じ捕獲の石は粒を0.05秒ずつずらす |
| 確定 | `CarryStone.BecameConfirmed` | ごく薄く黄色に光るだけ |

粒子はテクスチャなしの四角で、角の立った形にそろえました。パーティクルシステムは1つだけ持ち、`Emit`で位置と色を指定して使い回します。最初は小さすぎて見えなかったので、大きさを2.2倍にしました。

イベントは演出のためだけに足したもので、ルールの処理はどれも聞いていません。足したあとでルールテスト81項目がすべて通ることを確かめました。

## 7. 確かめ方の工夫

- **時系列の記録**: CLIからの1回の呼び出しに約0.7秒かかり、裏返りの瞬間などを取り逃がす。Unityの中に、イベントを受けて時刻つきで記録する係を仕掛け、あとで読み出した（掴む→置く→着地→確定→裏返り始め→回り終わり、の順を確認した）。
- **スローで撮る**: 撮るときだけ`Time.timeScale = 0.15`にして、粒子が見える瞬間を撮った。
- **数値で確かめる**: 人形の歩く動きは、部品の位置（体の高さ0.30→0.417、揺れ約7°、足の前後±0.3）で確かめた。
- **キー入力**: CLIから送れないので、対局中の操作とリスタートのボタンは手で確かめてもらった。
